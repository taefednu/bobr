# Prevent: живая проверка идёт по коду, которого уже нет

## Класс ошибки

Проверка руками или браузером опирается на поднятый стенд. Стенд остался с
прошлой смены — и отдаёт **тот код, с которым стартовал**.

У бэкенда это тихо и всегда: питон-процесс держит модули в памяти, правка файла
на диске ему безразлична (`--reload` спасает, но его в команде обычно нет).
У фронта на Vite наоборот — HMR подхватывает правки, поэтому половина стенда
свежая, а половина протухшая, и расхождение выглядит как дефект приложения.

Дороже всего то, что проверка **проходит**: экран отвечает, кнопки нажимаются,
и результат записывается как «проверено живьём». Проверено было прошлое.

Второй ход той же ошибки: свой сервер поднимается на занятый порт, падает с
`address already in use`, а `curl /health` **отвечает** — потому что отвечает
чужой, старый. Признак «сервис поднялся» получен, сервис не твой.

## Подтверждённые случаи

| Сессия | Что было |
|---|---|
| s173 (Platform) | Бэкенд крутился 2 часа с прошлой сессии. Свой uvicorn упал на занятом порту с кодом 0, `curl /health` ответил `{"status":"ok"}` — от старого. Живая проверка R31 пошла бы по коду без `has_video` и без гейта `is_lesson_learner`. Vite при этом крутился 10 часов и правки фронта отдавал СВЕЖИЕ |

## Детект

Перед живой проверкой — всегда:

```bash
ss -ltnp | grep -E ":8000|:3200"      # кто уже слушает
ps -o pid,etime,args -p <PID>          # ELAPSED = возраст процесса
```

`ELAPSED` больше времени твоей сессии — сервер стартовал до правок.

Признак упавшего своего запуска: в логе `[Errno 98] address already in use`,
а процесс завершился **кодом 0** (uvicorn считает это штатным выходом), то есть
фоновой задаче он отрапортует «успех».

## Правильный порядок

```bash
kill <PID>
until ! ss -ltn | grep -q ":8000"; do sleep 1; done   # дождаться освобождения
<команда запуска>
until curl -sf http://127.0.0.1:8000/health >/dev/null; do sleep 2; done
```

Ждать освобождения порта обязательно: запуск сразу после `kill` успевает
наткнуться на ещё живой сокет и молча упасть.

**`curl /health` признаком СВОЕГО запуска не является.** Доказательство — либо
пустой порт перед стартом, либо ответ, которого старый код дать не мог: новое
поле в JSON, новый код отказа, новый маршрут.

## Триггер

Применяй, когда:
- собираешься проверять руками или браузером;
- запускаешь сервер, который мог остаться с прошлой сессии;
- живая проверка даёт результат, противоречащий зелёным тестам, — сперва
  проверь возраст процесса, а уж потом ищи дефект.
