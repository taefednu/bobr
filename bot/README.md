# Telegram-бот родителя

Python 3.11+, aiogram 3, официальный Python SDK Convex. Отдельной базы нет.
Бот — только для родителя; занятия ребёнка открываются в браузере.

## Запуск

Скопируйте `.env.example` в `.env` внутри этой папки и заполните локально.
`BOT_SECRET` должен совпадать с env Convex; `TELEGRAM_BOT_TOKEN` — с токеном,
которым Convex проверяет Telegram initData. Значения никому не отправляйте.
`PUBLIC_APP_URL` — адрес Next.js; для WebApp-кнопки нужен HTTPS, доступный с телефона.
Адрес `/c/{code}` обслуживает детский frontend/core, бот его не реализует.

Из корня репозитория установка и запуск одной командой (Windows/Linux/macOS):

```sh
python bot/run.py
```

Команда создаст `bot/.venv`, установит зависимости и запустит long polling.
У одного токена должен быть один polling-процесс, без активного webhook.
Бот сам не меняет webhook и не сбрасывает ожидающие Telegram updates.
Для уже подготовленного окружения: `python -m bot`.

## Поведение

`/start`: язык → объяснение ИИ → согласие → имя → класс → цель/дата → код и
браузерная ссылка. Тексты бота — `texts.py` (uz-Latn и ru; uz требует вычитки носителем).
`/goal` меняет цель через Convex, `/child` добавляет ребёнка или выдаёт новый код
для последнего добавленного ребёнка. `/help` показывает команды и SUPPORT_CONTACT,
если он задан. Повторный `/start` в текущем процессе не создаёт ещё ребёнка.

`/progress`, `/settings`, `/pause`, `/delete` пока честные заглушки: в текущем
контракте нет нужных функций. `/delete` требует подтверждения, но не заявляет,
что удалил данные. Запросы серверных функций координируются в SCHEMA_REQUESTS.md.

Outbox опрашивается раз в 3 секунды. Готовый текст Convex отправляется без
переписывания и разметки, затем вызывается markSent. Отложенная отметка повторяется
без повторной отправки в рамках текущего процесса. После аварии доставка at-least-once:
дубликат возможен, если Telegram принял сообщение до потери процесса.
Несрочные сообщения: максимум одно за день по Asia/Tashkent, без отправки 21:00–08:00.
Кризисы обходят лимит и тихие часы. ABUSE_HOME/notifyParent=false отбрасываются;
текущий listUnsent не отдаёт категорию, поэтому основная фильтрация ABUSE_HOME
остаётся в Convex. Не пытайтесь распознавать кризис по тексту сообщения.

## Оставшиеся зависимости от core

- FSM, выбранный ребёнок и дневной счётчик находятся только в памяти процесса.
  После перезапуска нет API для восстановления родителя/детей/согласия; прохождение
  `/start` заново может добавить ребёнка повторно. Нужны lookup и идемпотентное создание.
- Дневной лимит после перезапуска требует серверного учёта. Без него это не гарантия
  одного сообщения в день при рестартах или нескольких процессах.
- API возвращает максимум 100 старейших записей без пагинации: отложенные сообщения
  могут скрыть более поздний кризис. Нужна серверная выдача срочных/доступных сообщений.
- consentAt, безопасный текстовый progress, каскадное удаление, preferences/pause,
  ежедневные сводки и forgotten-производители пока отсутствуют в доступном API.
- Актуальный API уже поддерживает improve/just_practice; устаревшие значения целей
  не отправляются. Историческая совместимость не нужна после обновления core.

## Проверка

```sh
python -m unittest discover -s bot/tests -v
```

Тесты используют фальшивые транспорт/API и фиксированные часы, без токенов,
Telegram-сообщений и записи в настоящий Convex. Для живого смоука пройдите `/start`
на обоих языках и попросите core подготовить событие outbox для вашего тестового
родителя. При доступных сервисах сообщение должно прийти за ≤5 секунд.
Нельзя подменять настоящий смоук успешными тестами с фальшивым транспортом.
