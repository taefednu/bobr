# Prevent: экран выдаёт неизвестное за ноль

## Класс бага

Состояние загрузки инициализируется нулём или пустым массивом, а отказ запроса не отличается
от честного «данных нет». Пользователь видит **факт**, которого не было.

Три формы, все встретились в одной сборке s165:

1. `error` ставится только когда упали **все** запросы (`p && r`), поэтому отказ одного показывает
   пустое состояние. Учитель с классами увидел «за вами не закреплён ни один класс».
2. **Зеркало того же:** починили один запрос, второй остался. Классы отрисовались, на каждой
   карточке встало «Учеников: 0» — и это выдумка, потому что счёт берётся из ростера, которого нет.
3. Счётчик заведён `useState(0)`, бейдж рисуется при `> 0`. Сбой **первого** запроса даёт
   молчаливое «непрочитанных нет», и учитель не открывает вкладку с тревогой о ребёнке.

4. **`Promise.allSettled` + `? value : []`** — четвёртая форма, поймана в s176 дважды за сессию.
   Отказ ЛЮБОГО запроса превращается в пустой массив, неотличимый от честного «данных нет».
   Карточка ученика печатала «Фидбэка пока нет», когда сервер отвечал **409**; раздел
   «Переписка» печатал «Пока нет переписок» над списком из четырёх детей, потому что одна
   строка локали обслуживала и «нет», и «не выбрано».

   **Отягчающее, ради которого форма выделена отдельно:** под проглоченным отказом стояла
   ФОРМА из четырёх полей, чья кнопка «Отправить» возвращала ту же 409. Пустое состояние
   врёт молча, а форма над ним заставляет человека работать впустую.

   Различать надо по **коду ответа** (`ApiError.status`), а не по тексту `detail`: тот не
   машинный и меняется свободно.

## Обнаружение

```bash
# ЧЕТВЁРТАЯ ФОРМА: отказ, схлопнутый в пустой массив
grep -nE 'status === "fulfilled" \? [a-z.]+ : \[\]|\.status === "rejected"' <файлы экрана>
# рядом: рисуется ли форма/кнопка отправки под этим же состоянием
grep -nE '<[A-Z][A-Za-z]*Form|onSubmit|Отправить' <файлы экрана>

# состояния, инициализированные нулём/пустым, рядом с загрузкой
grep -nE 'useState<?(number)?>?\(0\)|useState\(\[\]\)' <файлы экрана>
# условие ошибки, требующее падения ВСЕХ запросов
grep -nE 'status === "rejected".*&&.*status === "rejected"|if \(\w+ && \w+\) setError'
```

Вопрос на проверку: **какое из трёх состояний экран показывает при отказе — «пусто», «ноль» или
«не знаю»?** Если первые два — баг.

## Правильная форма

Неизвестность — **третье** состояние, а не значение по умолчанию.

```ts
const [count, setCount] = useState<number | null>(null);   // null = «не знаю»
// падение ЛЮБОГО запроса, чьи данные видны на экране:
if (a.status === "rejected" || b.status === "rejected") setError(...);
```

Правило одной строкой: **пустое значит «пусто», ноль значит «ноль», и ни то, ни другое не значит
«не смогли загрузить».**

Запасное число из уже загруженного окна — **тот же дефект в мягкой форме**: длина ленты это
занижение, поданное как факт. Честнее знак «неизвестно».

## Триггер

Применять, когда экран показывает число, список, счётчик или бейдж, взятый из запроса.
Особенно — когда запросов **два и больше**: почини один, и зеркало останется во втором.
