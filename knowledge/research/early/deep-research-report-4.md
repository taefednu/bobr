# Условия OpenAI, Anthropic и Google Gemini для пользователей младше 18 лет и API с персональными данными детей

**Дата проверки:** 17 ноября 2026 года, Asia/Tashkent.  
**Сценарий:** AI-тьютор для детей 11–12 лет; ребенок взаимодействует с вашим продуктом, а запросы отправляются в модель через API.  
**Файл:** [скачать полный отчет в Markdown](sandbox:/mnt/data/ai_tutor_under18_openai_anthropic_google_2026-11-17.md)

В исследовании использованы только первичные официальные условия, DPA, Help Center и developer/cloud-документация самих OpenAI, Anthropic и Google. COPPA, GDPR и иные законы ниже не трактуются самостоятельно: они упоминаются только там, где на них прямо ссылается вендор.

## Пять подтвержденных фактов для питча

1. **OpenAI API имеет явно описанный путь для продуктов с несовершеннолетними end users.** Services Agreement требует parent/guardian consent для minors, а under-18 guidance говорит не отправлять персональные данные ребенка младше 13 лет или applicable digital-consent age до внедрения ZDR. Для продукта на 11–12 лет это прямое vendor-level условие архитектуры данных. citeturn379111view0turn525283view2

2. **Anthropic consumer Claude и Anthropic API — принципиально разные режимы.** Claude.ai consumer — 18+, но Usage Policy отдельно предусматривает API-powered products, где minors непосредственно взаимодействуют с моделью, при условии выполнения minors guidance и применимых правил. citeturn200722view3turn379111view11turn200722view6

3. **Gemini Developer API/AI Studio и Google Cloud Generative AI по стандартным terms блокируют именно child-facing developer scenario:** API Client или Customer Application не может быть направлен на или likely accessed пользователями младше 18 лет. Parent consent в этих clauses не указан как исключение. citeturn379111view16turn525283view16

4. **“Не обучаем на API-данных” и “ничего не сохраняем” — разные вещи.** OpenAI API не использует данные для training по умолчанию с марта 2023 года, но default abuse logs могут сохраняться 30 дней; Anthropic запрещает training на Customer Content, но стандартно хранит API I/O до 30 дней и намного дольше при policy flags; Google paid Gemini API не использует prompts/responses для product improvement, но сохраняет ограниченные abuse/security logs. citeturn379111view2turn379111view3turn379111view10turn426033search1turn379111view18

5. **Education-режимы нельзя использовать как доказательство допустимости обычного API.** OpenAI ChatGPT for Teachers, Anthropic U.S. K-12 Terms и Google Workspace for Education имеют отдельные договорные конструкции. В частности, Google Workspace Education допускает under-18/all-ages на определенных Gemini education surfaces, одновременно Gemini Developer API и Vertex AI сохраняют 18+ child-facing restriction. citeturn200722view2turn200722view8turn525283view18turn525283view19turn379111view16turn525283view16

## Три вывода для продукта

1. **Для прямого AI-тьютора детям 11–12 лет стандартный Gemini Developer API/AI Studio и стандартный Google Cloud Generative AI/Vertex AI route сейчас конфликтуют с прямым текстом vendor terms.** Речь именно о договорном запрете child-facing API Client/Application, а не о самостоятельном выводе, что любой продукт такого типа юридически запрещен. citeturn379111view16turn525283view16

2. **OpenAI и Anthropic потенциально дают API-маршрут для minors, но privacy architecture должна проектироваться под конкретного вендора.** Для OpenAI under-13 guidance прямо связывает processing personal data с предварительным ZDR, причем ZDR approval-based и имеет endpoint/safety exceptions. Anthropic minors use предусмотрен policy, но ZDR тоже approval-based, а default и abuse retention имеют отдельные исключения; Covered Models могут вводить дополнительный retention даже для части ZDR deployments. citeturn525283view2turn379111view3turn525283view10turn426033search1turn426033search2

3. **Архитектуру стоит строить вокруг границы “ребенок → ваш сервис → API vendor”, а не вокруг consumer-chatbot правил.** Для этого отдельно фиксируются parental-consent flow там, где его требует vendor contract, age/safety controls, DPA и subprocessor map, retention mode, конкретные endpoints/models и минимизация передаваемых персональных данных. Consumer age limits и education exceptions сами по себе этого не заменяют. citeturn379111view0turn525283view2turn200722view6turn525283view18

## Противоречия и территориальные зависимости

У **Google consumer Gemini** нет одной универсальной возрастной цифры для всех поверхностей. Официальная mobile-app документация говорит 13+ или applicable local age, но одновременно разрешает supervised under-13 use при parent approval. Это не распространяется автоматически на Gemini Developer API: его Additional Terms отдельно запрещают child-facing API Clients under 18. Для EEA, Switzerland и UK есть еще одно API-specific правило: API Clients могут предоставляться пользователям только через Paid Services. citeturn581948search0turn581948search6turn200722view9

У **OpenAI** consumer Terms прямо отделены от Business/API Terms. Consumer minimum age — 13 или применимый более высокий local threshold, плюс parent/guardian permission under 18; API регулируется Services Agreement и отдельной Under-18 API Guidance.
