# Трек C — Telegram-бот родителя и демо-инфраструктура

**Владелец трека:** Руслан.

## Задача 1: Telegram-бот для родителя
- `/start` → экран согласия (что видит родитель: сводку, не переписку) → привязка к ребёнку по коду.
- Mini App `/parent` внутри Telegram: проверка `initData` (HMAC по токену бота) на сервере, без неё — 401.
- Пуш «научил(а) Bobr …» в момент taught_bobr (подписка на событие из трека B).
- Кризис-пуш по таблице спеки: SELF_HARM — родителю срочно, без цитат; ABUSE_HOME — родителю НЕ сообщать;
  GROOMING — родителю. Маршрутизация уже есть: `crisisRouting` в `lib/safety/crisis.ts` — используй её.

## Задача 2: демо-инфраструктура
- Деплой: Vercel (Next) + Convex prod; ссылка и QR для жюри.
- Офлайн-демо: `DEMO_MODE=replay` (ответы из `llmCache`), запасное видео (спека «Сбои и демо»).
- `scripts/demo-reset` — сброс демо-ученика и родителя к началу демо-пути.
- `docs/DEMO_RUNBOOK.md` — пошагово: что запускать, что нажимать, что делать при сбое сети.

## Зона (правит только этот трек)
- новые `convex/telegram.ts`, `convex/http.ts` (вебхук), `lib/telegram/**`
- `scripts/demo-*`, `docs/DEMO_RUNBOOK.md`, `docs/DEMO_OFFLINE.md`, конфиг деплоя (`vercel.ts` и т. п.)
- Mini App-обвязка вокруг `/parent` (сам экран `/parent` — трек A; договаривайтесь о компоненте)

## Можно использовать, нельзя менять
`lib/safety/crisis.ts` (маршрутизация — «не режем никогда»), схему (заявки в `SCHEMA_REQUESTS.md`: таблица
`parents` уже есть — `linkCode`, `telegramChatId`). Токен бота и секреты — только в env Vercel/Convex, не в файлах.
Безопасность: никакой переписки ребёнка в Telegram, только сводка; ПДн не в логи.
