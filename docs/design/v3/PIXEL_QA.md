# Сверка экрана с эталоном 1 к 1

Зачем: вёрстка «на глаз» дала экраны, которые владелец назвал поделкой. Экран считается готовым только по замерам и снимку.

## Эталон

| Экран | Картинка | Замеры | Страница сверки | Боевой маршрут |
|---|---|---|---|---|
| Главный | `docs/design/v3/1-home.png` | `measure/home.json` | `/dev/v3/home` | `/home` |
| Мой дом | `docs/design/v3/2-house.png` | `measure/house.json` | `/dev/v3/house` | `/house` |
| Чат с Ustoz | `docs/design/v3/3-chat.png` | `measure/chat.json` | `/dev/v3/chat` | `/chat` |
| Профиль | `docs/design/v3/4-profile.png` | `measure/profile.json` | `/dev/v3/profile` | `/profile` |

Кадр всегда 390×845 CSS px, масштаб картинки 1024 / 390 = 2.6256. Числа в `measure/*.json` сняты с картинки по сетке и
приведены к общей сетке: поля 16 px, карточки 358 px, колонки одинаковой ширины, один таб-бар на всех экранах. Где картинка
и JSON расходятся на 1–5 px из-за неровности генерации, главный JSON. Менять JSON можно только с причиной в отчёте.

## Цикл для каждого экрана

1. **Состав.** Выпиши объекты экрана: какой общий компонент и токен, какой ассет из `ASSETS.md`.
2. **Разметка.** Каждому блоку из JSON поставь `data-ref="<id>"` на тот элемент, чей прямоугольник измеряем.
   Блока в JSON нет, а на экране он нужен — добавь в JSON и напиши об этом в отчёте.
3. **Страница сверки** `/dev/v3/<экран>`: настоящие компоненты экрана с фикстурой, где тексты и числа как на эталоне. Закрыта
   в production через `notFound()`. Боевая страница использует те же компоненты с данными из Convex.
4. **Прогон:**
   ```bash
   node scripts/ref-check.mjs home
   ```
   Выход: `.ref-check/home/report.md` (таблица эталон / страница / Δ) и `.ref-check/home/compare.png` (эталон, страница,
   наложение 50 % с рамками блоков: зелёная в допуске, красная нет).
5. **Глаза.** Открой `compare.png`. Проверь то, что прямоугольники не ловят: размер и вес текста, базовые линии, радиусы,
   тени, градиент, положение персонажа внутри баннера, обрезку арта по краю карточки.
6. **Итерация** до кода выхода 0 и чистого снимка. Потом боевой маршрут на живых данных: без переполнения и ошибок консоли.

## Критерии «готово»

| Проверка | Порог |
|---|---|
| Положение и размер каждого блока | ±2 px по x, y, w, h |
| Блоки из JSON на странице | все |
| Горизонтальное переполнение, ошибки консоли | 0 |
| Цвет фона, карточек, кнопок (пипеткой по снимку) | ΔE заметно не отличается, значения из таблицы README |
| Текст | кегль и насыщенность как на эталоне, одна строка там же, где на эталоне |
| Боевой маршрут ru и uz | ничего не обрезано, uz длиннее и не ломает сетку |
| `prefers-reduced-motion` | вся информация на месте |

Попиксельный процент как оценку не используем: текст и арт отрисованы другим движком, и цифра ничего не скажет. Смотрим
геометрию числами и всё остальное наложением.

## Отчёт агента экрана

В отчёте: загруженные скиллы, изменённые файлы, строка результата `ref-check`, таблица блоков со значением Δ больше 1 px, путь
к `compare.png`, снимки боевого маршрута ru и uz, что не сделано. Оркестратор открывает `compare.png` сам и принимает экран
только по нему.
