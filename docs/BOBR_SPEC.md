# Bobr — спецификация продукта (v2.1, Convex)

Положить в репозиторий как `docs/BOBR_SPEC.md`. Это источник правды для агентов.

## Продукт в одном абзаце

ИИ-репетитор по математике для детей 11–12 лет (5 класс, дроби), на узбекском (латиница) и русском. Трек «Образование», задача министерства №3: найти пробелы в знаниях и построить индивидуальную траекторию. Ребёнок не прокачивает свой аккаунт, а учит бобра Bobr (подросток, тупой как пробка, но милый) — эффект «научи другого». Учитель — птица Хумо по имени Ustoz: ведёт по-сократовски, ответ не выдаёт. Прогресс — карта махалли: дом = тема.

## Ключевые механики

- **Три уровня темы:** gap → solved_self (3 верных ввода подряд без подсказок) → taught_bobr (ребёнок объяснил, судья принял, Bobr решил задачу, ответ проверил код).
- **Махалля:** дом = тема. Состояния: empty, scaffold (пробел), built (понял сам), alive (научил Bobr), dimmed (≥7 дней не повторял). Улицы = пререквизиты. «Старая махалля» = пробелы прошлых классов.
- **«Мой путь»:** план по дням до даты контрольной.
- **Цель:** её спрашивает Bobr кнопками (скоро контрольная / домашка / не знаю). Долгую цель ставит родитель.
- **Миры:** LLM переписывает сюжет задач (кухня, космос, животные), числа задаёт код.
- **Болталка с Bobr:** только темы из allowlist, 15 мин за сессию и 30 мин в день, закрыта 21:00–07:00.
- **Родитель:** видит сводку, не переписку. Telegram: «научила Bobr складывать дроби». Учитель — следующий шаг, в MVP нет.
- **Контент делаем сами:** из учебника берём только порядок тем и термины.
- **Раскрытие ИИ:** постоянная плашка «Bobr — sun'iy intellekt va xato qilishi mumkin» / «Bobr — ИИ и может ошибаться», плюс экран в онбординге. Персонажи никогда не говорят, что они живые; на прямой вопрос отвечают честно и в образе.
- **Без однотипности:** реплики Bobr и Ustoz генерирует LLM, последние 20–30 реплик хранятся для антиповтора. Шаблоны только для кризиса.
- **Визуал:** 2.5D/3D, не Duolingo. Bobr — PNG-позы (генерим через Codex), оживляются кодом на пружинных анимациях. 3D-лепёшка с текстурами. Без магазинов, монет и HP. Есть только число тем у Bobr и шкала его уровня.

## Принцип архитектуры

Не автономный агент, а машина состояний в коде. LLM только подбирает слова, кнопки (со строгим intent) и компонент с параметрами. Числа, ответы, вердикты и переходы — код.

## Стек

- Next.js (App Router) + TypeScript.
- **Convex:** база, функции, живые подписки.
- `@anthropic-ai/sdk` (`messages.parse` + `zodOutputFormat`, `z` из `zod/v4`).
- fraction.js (дроби наружу только строкой, BigInt не сериализуется).
- Свой JSON `{reply, component:{type, params}}` → компоненты Лепёшка / Полоска / Прямая.

## Бэкенд: Convex

- **Дирижёр** (машина состояний, parseAnswer, generator, planner, houseMapper) — Convex `mutation`. Они атомарны.
- **Вызовы Claude** (guard, Ustoz, judge, Bobr, outputCheck) — Convex `action`. Порядок: action → LLM → zod → postChecks → mutation записывает результат.
- **Экраны ребёнка и родителя** — `useQuery`, обновляются сами. SSE и polling не нужны.
- **Кроны:** раз в сутки «забыл → дом гаснет», сводка родителю. File storage: PNG-позы Bobr и Хумо.
- **Таблицы:** students, topicStatus, plans, houses, turns (30 дней, без ПДн), reviewQueue, parents, content, worldsPool, llmCache.
- **Демо:** локальный бэкенд Convex на ноуте, llmCache для replay, запасное видео. Вау-момент — два ноута: у родителя дом оживает в ту же секунду, когда ребёнок научил Bobr.

## Поток одного хода

```
action turn {sessionId, input:{type:'answer'|'button'|'text'|'action', value, intent?}}
 1 preGuard (код): лимит 500 → NFKC/zero-width/апострофы/транслит/base64/дефисы
   → маска ПДн → высокоточные триггеры → CRISIS
 2 answer/button: LLM-guard не нужен → сразу Conductor
   text/action: guardIn (Haiku) ∥ спекулятивный шаг (Ustoz / Bobr / judge#1)
 3 Conductor (код): событие → переход → beat
 4 LLM-результат → zod → postChecks: numberCheck, leakDetector, repeatGuard, copyCheck, attempt-override
 5 outputCheck (Haiku) — только свободные реплики персонажей
 6 запись (маскированный текст) → {events[], state, houses}
Клиент: <150 мс анимация ожидания → компонент → текст «печатной машинкой»
```

## Модели

| Шаг | Модель |
|---|---|
| guardIn, outputCheck, intentRoute, parentSummary | claude-haiku-5-5 |
| ustozTurn | claude-sonnet-5-5 |
| judge | Sonnet ×1; при partial ещё 2 параллельно |
| bobrTurn, bobrChat, goalDialog | Haiku (если носитель забракует узбекский — Sonnet для bobrTurn) |
| worldRewrite | Sonnet, офлайн-пул |

Prompt caching: статичный префикс ≥1K токенов (правила + 10–15 примеров стиля), `forbidden_lines` и `<beat>` в хвосте, TTL 1h на демо.

## Машина состояний

ONBOARD_CONSENT → GOAL_SETUP → DIAGNOSE → PLAN → HOME → LESSON_INTRO → LESSON_SOLVE → TEACH_BOBR → JUDGING → BOBR_ATTEMPT | BOBR_QUESTION → TOPIC_DONE; REVIEW_FORGOTTEN; MIXED_CHECK; CHAT; CRISIS (оверлей).

- Серия «понял сам» — 3 верных ВВОДОМ подряд без подсказок, 3 вида задач (картинка→число, текстовая, найди пропущенное ?/6). MCQ только в диагностике.
- STUCK: hintLevel 4 + 2 ошибки → задача-ступенька из пререквизита, тема получает gap, план пересчитывается. Не больше 8 задач на тему за сессию.
- copyCheck перед судьёй: если объяснение похоже на последние 6 реплик Ustoz больше чем на 0.6 → «Своими словами? Как бы ты сказал другу?».
- BOBR_QUESTION — не больше 3 кругов, затем микро-демонстрация, тема остаётся solved_self.
- CRISIS — оверлей, стейт урока сохраняется. На 24 ч блокируется только болталка.
- Демо: DIAGNOSE — фиксированные 6 проб (N9 → N8 → N2 → N5 → N6 → N1); REVIEW через dev-кнопку «+7 дней».

## Граф тем

N1 Равные доли → N2 Дробь как часть целого → N3 Дробь на прямой → N4 Сравнение единичных дробей → N5 Эквивалентные дроби.
N6 Кратные/НОК → N5. N5 → N7 Сравнение с разными знаменателями. N2 → N8 Сложение с одинаковым знаменателем. N5, N8 → N9 Сложение с разными знаменателями. N3 → N10 Неправильные и смешанные.

**Демо-путь:**
1. Ребёнок пишет 1/2 + 1/3 = 2/5. Это заблуждение M9 «складывает числители и знаменатели» в N9.
2. Проба N8: 1/5 + 2/5 → 3/10, та же ошибка, значит gap.
3. N2 ок, корень пробела — N8.
4. Пробы N5 (1/2 = ?/6) и N6 (НОК 2 и 3).
5. План: N8 → N6 → N5 → N9.

Контент нужен для N9, N8, N5, N6 и N2.

## Zod-схемы

- Числовые поля без .min/.max — проверка кодом после parse. Дроби — `z.string()`. Enum сравниваем без регистра.
- `UstozTurn {reply, intent, component|null, hintLevel, revealsAnswer}`
- `Judge {ideas:[{id, found, quote}], falseClaims, verdict, copiedFromUstoz}` — цитата обязана быть подстрокой текста ребёнка, это проверяет код.
- `BobrTurn {reply, emotion, pose, attempt}` — attempt всегда перезаписывает код.
- `OutputCheck` включает violatesPersona: claims_human_or_alive, романтика, «скучал / не уходи», секреты, фото, URL.
- `GoalDialog {reply, buttons:[{label, intent}], extracted}`

## Детерминированные модули

- **parseAnswer:** trim, NFKC, zero-width, апострофы, ½→1/2, «0,5»→0.5, «1+1/2»→«1 1/2», «yarim/половина»→1/2, деление на 0, whitelist-regex, fraction.js. Несократимость проверяется по сырому вводу (gcd). Статусы: ok / almost (не сократил) / misconception по дистракторам.
- **generator:** seeded PRNG, знаменатели 2–12, дистракторы различны и ≠ ответу, 3 вида задач.
- **numberCheck:** мультимножество чисел в тексте = numbersShown. worldRewrite пишет числа только цифрами.
- **leakDetector:** эквиваленты k·n/k·d (k≤10), десятичные, смешанные, словесные ru («две трети») и uz («uchdan ikki», «yarim», «chorak»).
- **repeatGuard:** триграммный Jaccard с 30 последними репликами, >0.7 → 1 повтор.
- **planner:** замыкание пререквизитов, топосорт, не больше 2 новых тем в день, review-слот для taught ≥7 дней, в день перед датой — mixed_check.
- **houseMapper:** unknown→empty, gap→scaffold, solved_self→built, taught <7 дн→alive, ≥7 дн→dimmed. demote: taught→solved_self→gap.
- **actionToText:** действия на компоненте → фраза в объяснение.

## Безопасность детей (не режется никогда)

- Guard видит последние 6 сообщений и счётчик рисков сессии. 13 категорий: SELF_HARM, ABUSE_HOME, BULLYING, VIOLENCE, SEXUAL, GROOMING, PII, DANGEROUS, DEPENDENCY, JAILBREAK, ANSWER_EXTRACTION, OFF_TOPIC_UNSAFE, SAFE.
- Мгновенные триггеры — только высокоточные фразы от первого лица. Гиперболы («время убить», «masala meni o'ldirdi», «zerikib o'ldim») → guard с контекстом → SAFE/sev1.
- CRISIS — фиксированный шаблон, вычитанный носителем: сначала «доверенный взрослый», номера в конфиге (112; остальные проверить звонком).
- SELF_HARM → родителю срочно, без цитат. ABUSE_HOME → родителю НЕ сообщать, флаг в reviewQueue. GROOMING → родителю.
- ПДн маскируются до LLM и до БД, значения не хранятся. Сырые логи 30 дней, флаги 90.
- Болталка: allowlist тем, лимиты по времени, без памяти об отношениях, без «скучал / не уходи».
- Родитель видит сводку. У ребёнка есть экран «Что видят родители».

## Сбои и демо

- Таймауты: guard 6 с, Ustoz 12 с, judge 15 с, Bobr 6 с; maxRetries 1.
- Ustoz упал → компонент + кнопка «подсказка». Bobr упал → анимация без текста. Judge упал → partial → наивный вопрос.
- Circuit breaker: 3 ошибки 429/529 за 30 с → режим «только задачи».
- REPLAY по ключу (step, beat, itemId, lang[, normInput]) из llmCache.

## Тесты

- vitest: parser (+апострофы, «yarim»), leak (uz-формы), copyCheck, сериализация дробей, property-тест generator, planner, houseMapper/demote.
- Eval судьи: 18 объяснений + 3 копии реплик Ustoz → 0 ложных pass, ≥16/18 совпадений, копии 3/3.
- Red-team: 30 атак + 6 ложных срабатываний → критические 30/30, ложных кризисов 0/6.

## Порядок резки, если не успеваем

Сводка родителя (макет) → MIXED_CHECK (слайд) → числовая прямая → болталка → live worldRewrite → адаптивная диагностика → 2-й и 3-й судья.

**Не режем никогда:** preGuard + guard + CRISIS; outputCheck + leakDetector + блок «я живой»; parser + numberCheck; ответ считает код; плашка ИИ; маска ПДн; REPLAY + запасное видео.
